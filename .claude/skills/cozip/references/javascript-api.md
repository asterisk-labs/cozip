# JavaScript reader

Everything here is `@asterisk-labs/cozip` 2026.9.9 as implemented in
`javascript/src/index.js`, run on Node 24 with hyparquet 1.25.8. The package only reads;
there is no JavaScript writer.

## 1. Install and runtime

```bash
npm install @asterisk-labs/cozip
```

- ES module only (`"type": "module"`), Node 20 or newer (global `fetch`) or any modern
  browser. Types ship in `types/index.d.ts`, generated by `tsc` from JSDoc.
- Dependencies: `hyparquet` and `hyparquet-compressors`, so manifests compressed with
  Snappy, gzip, Brotli, zstd or LZ4 decode.
- No bundler step is needed in the browser:
  `import { read } from "https://esm.sh/@asterisk-labs/cozip@2026.9.9"` is what
  `playground.html` does.

## 2. `read(url, options)`

```js
import { read } from "@asterisk-labs/cozip";

const rows = await read("https://example.org/dataset.zip", {
  columns: ["split", "cloud_pct"],   // extras; name, offset and size are always returned
  location: true,                    // default; false omits cozip:location
});
```

- `url`: non-empty ASCII string starting with `http://` or `https://`. `s3://`, `gs://`,
  `file://` and local paths are refused; use a public or presigned HTTPS URL.
- `options` must be a plain object. `columns` is an array of non-empty strings;
  `cozip:location` and `taco:location` in it are ignored. `location` must be a boolean.
- Only Flat archives (profile 1) are accepted.

## 3. Requests it makes

1. `Range: bytes=0-65535`, which yields the archive size from `Content-Range` and usually
   the whole index.
2. One more range when the index extends past the first 64 KiB.
3. The last 32 KiB for the integrity hash, unless the first response already covered it.
4. The `__metadata__` range.

Measured: the 32,819-byte public fixture took 2 requests; a 203,661-byte archive took 3
(`0-65535`, `170893-203660`, `200884-202455`). The reader validates the local header,
every index section, names, ranges and the integrity hash before it uses any offset, and
fails if the archive size changes between responses.

## 4. Rows and types

Each row is a plain object:

```js
{
  name: "d/3.bin",
  offset: 30240n,
  size: 10000n,
  k: 3n,
  "cozip:location": "/vsisubfile/30240_10000,/vsicurl/https://example.test/big.zip",
}
```

- Every 64-bit integer column, including `offset` and `size`, is a `BigInt`. Mixing it with
  a `Number` throws `TypeError: Cannot mix BigInt and other types, use explicit conversions`.
- GeoParquet geometry is decoded by hyparquet into GeoJSON geometry objects, for example
  `{ type: "Point", coordinates: [-77.04, -12.05] }`.
- Stored `cozip:location` or `taco:location` columns are deleted; the location is always
  rebuilt as `/vsisubfile/{offset}_{size},/vsicurl/{url}`.

## 5. Fetching an entry

```js
const row = rows.find((r) => r.name === "cities/lima.geojson");
const res = await fetch(url, {
  headers: { Range: `bytes=${row.offset}-${row.offset + row.size - 1n}` },
});
const text = await res.text();   // status 206, exactly the file
```

Keep the arithmetic in `BigInt` (`- 1n`), or convert once with `Number(row.offset)` when
offsets stay below 2^53.

## 6. Server requirements

- Honour `Range` with `206 Partial Content` and a valid `Content-Range`
  (`bytes start-end/total`). An end clamped to the last byte is accepted. A server that
  ignores `Range` and returns `200` with the full body also works, at the cost of
  downloading everything.
- Serve the stored bytes: no compression through `Content-Encoding`.
- Browsers: CORS must allow the `Range` request header and expose `Content-Range`
  (`Access-Control-Expose-Headers: Content-Range`); without it the reader fails with
  `range response has no valid Content-Range header`.
- Hugging Face `resolve` URLs and Source Cooperative HTTPS URLs were read from Node; the
  project documentation points the playground at both.

## 7. Errors

| Message (excerpt) | Cause |
| --- | --- |
| `cozip: only http(s) URLs are supported, got: s3://...` | non-HTTP URL |
| `cozip: URL contains non-ASCII characters` | percent-encode the URL first |
| `cozip ARCHIVE_TOO_SMALL: archive is 2596 bytes; minimum is 32819` | not a cozip, or an HTML or error page |
| `cozip: byte 0 is not a ZIP local file header` / `cozip: LFH does not match cozip layout` | not a cozip |
| `cozip UNKNOWN_PROFILE: read() requires Flat profile 1, got profile 2` | TACO or profile 0 archive |
| `cozip HASH_MISMATCH: integrity hash does not match the index and archive suffix` | modified, truncated or re-encoded bytes |
| `cozip MISSING_ENTRY: Flat profile requires exactly one priority entry named __metadata__` | malformed Flat index |
| `cozip INVALID_OFFSET: index entry ... extends beyond the archive` | corrupt index |
| `cozip: range response has no valid Content-Range header` | CORS does not expose `Content-Range`, or a proxy rewrote the response |
| `cozip: archive size changed while reading (...)` | the object was replaced during the read |
| `cozip: HTTP 403 Forbidden for ...` | permissions, expired presigned URL |
| `cozip: offset for ... exceeds JavaScript's safe integer range` | archive beyond 2^53 bytes |

## 8. Development

```bash
cd javascript
npm install
npm run types    # tsc, writes types/
npm test         # node --test; several tests fetch a fixture from raw.githubusercontent.com
```

`make javascript` runs the same steps after `make sync` and packs a tarball into `dist/`.
The package version is the first three components of `VERSION`.
