## 2. Sources of truth and generated files

| Edit this | Never edit | Regenerated by |
| --- | --- | --- |
| `core/cozip.c`, `core/cozip_read.c`, `core/cozip.h` | `r/src/cozip.c`, `r/src/cozip_read.c`, `r/src/cozip.h` | `make sync` |
| `core/libzip/`, `core/zlib/` (upgrade steps in `core/CMakeLists.txt`) | `r/src/libzip/`, `r/src/zlib/` | `make sync` (`rsync --delete`) |
| `core/karu/` (replace it whole with a tagged karu release, never patch it) | `r/src/karu/` (`include/`, `src/`, `VERSION`, `LICENSE`) | `make sync` (`rsync --delete`) |
| `r/src/Makevars.in`, `r/src/Makevars.win.in` | `r/src/Makevars`, `r/src/Makevars.win` (ignored) | `r/configure`, `r/configure.win` at install |
| `VERSION`, `LICENSE` | `python/VERSION`, `python/LICENSE`, the version fields of `r/DESCRIPTION`, `julia/Project.toml`, `javascript/package.json` | `make sync` |
| roxygen comments in `r/R/*.R` | `r/man/*.Rd`, `r/NAMESPACE` | `roxygen2::roxygenise()` (run by `make r`) |
| release tag | `julia/Artifacts.toml` | release workflow |
| `javascript/src/index.js` JSDoc | `javascript/types/` (ignored) | `npm run types` |

Build outputs are ignored and are not source: `core/build*/`, `python/cozip/_lib/`,
`dist/`, `javascript/node_modules/`, `r/src/*.o`, `r/src/*.so`, `r/src/version.h`,
`r/src/Makevars`, `r/src/Makevars.win`.

`make sync` overwrites the copies first, so an edit made directly in `r/src/` is silently
lost, then verifies the copies and version fields (`check: cozip.c drift` and similar on
failure) and prints `sync OK <version>`. `.pre-commit-config.yaml` runs it on every commit
once `pre-commit install` has been run; `.githooks/pre-commit` is inactive (it calls the
removed `tools/sync_version.sh` and exits).

The optional DuckDB extension lives in asterisk-labs/cozip_reader and is not part of this
repository. Nothing here builds, pins or loads it; its changes go to that repository.

## 3. Build and test commands

There is no CI on pushes: `release.yml` runs only for `v*` tags. Run the suites locally.

| Command | What it does |
| --- | --- |
| `make lib` | configure `core/build` with Ninja, build, copy the library to `python/cozip/_lib/` (needs libcurl and OpenSSL for the reader) |
| `make sync` | propagate `VERSION` and `LICENSE`, mirror `core/` (karu included) into `r/src/`, check for drift |
| `make python` | `make lib`, `pip install -e python`, `pytest tests/ -v`, `python -m build --wheel` (needs `pytest` and `build`) |
| `make r` | `make sync`, roxygen, `R CMD INSTALL`, `R CMD build` and `R CMD check` into `dist/` |
| `make julia` | `make lib`, then `Pkg.test()` with `COZIP_LIB_PATH` pointing at the staged library |
| `make javascript` | `make sync`, `npm install`, `npm run types`, `npm test`, `npm pack` into `dist/` |
| `make all` | `sync lib python r julia javascript` |
| `make clean` | remove builds, staged libraries, `dist/`, `node_modules`, generated types |

C tests (not built by `make lib`):

```bash
cmake -S core -B core/build-tests -G Ninja -DCOZIP_BUILD_TESTS=ON
cmake --build core/build-tests
ctest --test-dir core/build-tests --output-on-failure
```

`-DCOZIP_READER=OFF` builds the writer alone, without C++, libcurl or OpenSSL. Reading then
fails with `UNSUPPORTED` and only `cozip_taco_c_api` runs. CMake finds libcurl 7.83 or newer
and OpenSSL 3 (on macOS the SDK curl and Homebrew `openssl@3` work).

Python tests against a specific library, without reinstalling:

```bash
COZIP_LIB_PATH=$PWD/core/build-tests/cozip.dylib python -m pytest python/tests -q
python -m pytest python/tests/test_taco_internal.py::TestWrite -q
```

After editing C, rebuild before testing any binding: the editable Python install, R and
Julia keep loading whatever library they found before.

Sanitizers (ASan and UBSan; ctest and the Python suite pass this way on macOS arm64):

```bash
cmake -S core -B core/build-san -G Ninja -DCOZIP_BUILD_TESTS=ON -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_C_FLAGS="-fsanitize=address,undefined -fno-omit-frame-pointer" \
  -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -fno-omit-frame-pointer" \
  -DCMAKE_SHARED_LINKER_FLAGS="-fsanitize=address,undefined" \
  -DCMAKE_EXE_LINKER_FLAGS="-fsanitize=address,undefined"
cmake --build core/build-san && ctest --test-dir core/build-san --output-on-failure

# macOS: inject the runtime into Python; the subprocess import test cannot run this way
COZIP_LIB_PATH=$PWD/core/build-san/cozip.dylib \
DYLD_INSERT_LIBRARIES=$(clang -print-file-name=libclang_rt.asan_osx_dynamic.dylib) \
ASAN_OPTIONS=detect_leaks=0 \
python -m pytest python/tests -q -k "not test_private_module_has_a_lightweight_import"
```

ZIP64 run, for any change to planning, sizes or verification (about 5 seconds and 4 GiB of
disk; the source is sparse, the archive is not):

```python
from pathlib import Path
import pyarrow as pa, cozip

big = Path("big.bin")
with open(big, "wb") as f:
    f.truncate((1 << 32) + 12345)
Path("small.txt").write_bytes(b"after the big one\n")
table = pa.table({"name": ["big.bin", "small.txt"], "path": ["big.bin", "small.txt"]})
out = cozip.write("z64.zip", table)
print(cozip.read(out)[["name", "offset", "size"]])   # offsets 149 and 4294979829
big.unlink()
```

Then run `python .claude/skills/cozip/scripts/check_cozip.py z64.zip` and delete the
archive.

## 4. Test suites and what they guard

| Suite | Guards |
| --- | --- |
| `core/tests/test_taco.c` | TACO plan and write, entry order with padding before the priority block, opaque payloads, spec 14.2 name rules, regular-file and missing-source errors, plan drift, output aliasing, index guards, the `0xFFFFFFFF` boundary and the ZIP64 header size, duplicates and reserved names, Flat zero-byte and `in_index` handling, post-write verification |
| `core/tests/test_read.c` | Flat reads, index validation, transport errors and location mapping |
| `python/tests/test_smoke.py` | Flat archive bytes (header, index, hash, EOCD), name rules, Unicode paths, `read()` argument validation, `zipfile` compatibility, the staging contract, schema metadata and GeoParquet round trips (geopandas optional) |
| `python/tests/test_reader.py` | Flat reads over files and HTTP, projections, corrupt archives and extension independence |
| `python/tests/test_taco_internal.py` | the private boundary (`API_VERSION`, not exported, no heavy imports), plan and write rules, padding placement, hash, drift and tampering, raw `lib` calls for post-write checks |
| `r/tests/testthat/test-smoke.R` | the Python smoke suite for R, plus sf and geoarrow round trips |
| `r/tests/testthat/test-read.R` | Flat reads, projections and errors |
| `julia/test/runtests.jl` | writer tests, Flat reads, GeoParquet and the Windows read guard |
| `javascript/test/cozip.test.js` | the reader against a remote fixture, options, malformed index, profile rejection, hash, reserved names, clamped `206` responses |

The R and Julia suites reuse the Python fixtures (`hello cozip\n` times 8, `bytes(range(256))`
times 160) and constants; keep the three in step when behaviour changes.
`python/tests/conftest.py` provides `range_server`, a local HTTP server for `tmp_path` that
honours single `Range` requests and `If-Match`, and records the requests and bytes served.
Run R tests in a UTF-8 locale; under `LANG=C` the Unicode path test fails.

## 5. Where validation belongs

- Physical rules shared by every writer (name syntax, ASCII, reserved names, uniqueness,
  sizes, sources, layout arithmetic, profile name rules) live in `core/cozip.c`, with
  messages that name the entry and the rule, citing the spec section for profile rules.
  Bindings must not re-implement them differently.
- Bindings check what C cannot see or should not pay for: argument types, NUL bytes, table
  columns, reserved input columns, Parquet schema and values, friendlier early messages for
  missing files, and `read()` arguments before any read. Messages start with `cozip: `.
- Reader-side validation of the index lives in `core/cozip_read.c` for Python, R and Julia,
  in `javascript/src/index.js`, and in cozip_reader. `cozip_read.c` keeps cozip_reader's
  messages and their order. Readers never trust stored location columns.
- Python, R and Julia expose the same API (`write`/`create`, `stage_metadata`,
  `stage_create`, `read(columns, location)`); a new check or option lands in all three.

## 6. Changing the format or a profile

1. Change `SPEC.md` first (version line and date), in RFC 2119 terms. Registered profile
   values and reserved names are never reassigned. Raise ambiguities with the maintainers
   instead of settling them in code.
2. Implement writer rules in `core/cozip.c`, run `make sync`, add C and Python tests.
3. Update every reader: `core/cozip_read.c` (Python, R and Julia), `javascript/src/index.js`
   and the optional DuckDB extension in cozip_reader.
4. Update `docs/*.html`, the READMEs, `docs/taco-writer-internal.md` for profile 2, and
   this skill.
5. Regenerate or recheck the public fixtures (asterisk-labs/cozip-api-fixtures) when the
   layout changes; their revisions are immutable test targets.
6. Record the change in `CHANGELOG`, saying whether existing archives stay valid and
   whether old readers keep working.

## 7. Changing the C ABI or a binding API

- Public functions start with `cozip_` and carry `COZIP_API`; the release build fails if
  any other symbol is exported.
- Update by hand: the cffi `cdef` and constants in `python/cozip/_core.py`, the structs and
  `ccall`s in `julia/src/LibCozip.jl`, `r/src/cozip_glue.c` and its registration table.
  Nothing verifies them against `cozip.h`, and a mismatch corrupts memory silently.
- The reader functions return heap buffers and messages (`char **out_error`) instead of a
  `cozip_error_t`, so long URLs are never truncated. Every binding releases both with
  `cozip_free`, also on error, and R copies the message before `Rf_error` jumps out.
- Struct changes to `cozip_taco_plan_t` bump `COZIP_TACO_PLAN_VERSION` and
  `cozip._taco.API_VERSION` together (`taco-profile.md`).
- R man pages come from roxygen comments; rerun roxygen after signature changes.

## 8. Versioning and releases

CalVer `YYYY.M.D` in `VERSION`. R and Python use it as is; Julia and npm use its first
three components. Observed release sequence:

1. Set `VERSION`, run `make sync`.
2. Add a `CHANGELOG` section for the version, copying the heading format of the previous
   release, and its compare link at the bottom.
3. Run the suites above. Commit as `prepare the <version> release`, tag `v<version>`, push
   `main` and the tag.
4. `release.yml` checks that the tag equals `VERSION` and the Python copies; builds and
   tests libcozip on Linux x86-64 and aarch64 (manylinux 2.28), macOS aarch64 and x86-64
   (one library and one wheel per architecture, no universal build) and Windows x86-64,
   with libcurl and OpenSSL linked statically from vcpkg (`core/vcpkg.json`,
   `core/triplets/`), ctest, a check that no curl or crypto library is a dynamic
   dependency, and the symbol check; runs R CMD check on three systems, the
   Julia tests against the new libraries and the npm tests; builds and tests wheels and the
   sdist; publishes the GitHub release, PyPI (trusted publishing, environment `pypi`) and
   npm (environment `npm`); and pushes a `chore(julia): regenerate Artifacts.toml` commit
   to `main`.
5. Pull that commit, then register Julia in AsteriskRegistry with the command in
   `julia/UP`. Registering before pulling ships stale binaries without any error.
6. After npm has the release, update the pinned
   `https://esm.sh/@asterisk-labs/cozip@<version>` import in `playground.html`.
7. r-universe rebuilds R from `main` on every push, independently of tags.
8. The optional DuckDB extension is released from cozip_reader through
   duckdb/community-extensions, independently of this repository.

## 9. Conventions

- Commit subjects are short, lowercase and imperative (`protect reader-owned location
  columns`, `add the TACO plan and write API`). Bot and dependabot commits use `chore(julia):`,
  `ci:` and `deps:` prefixes.
- `CHANGELOG` follows Keep a Changelog with `Added`, `Changed`, `Fixed`, `Removed` (and
  occasionally `Internal`).
- C: C11 on the cozip target only (vendored code keeps its own flags), `-Wall -Wextra
  -Wpedantic -Wshadow`, byte-wise little-endian helpers, checked u64 arithmetic
  (`add_u64`), every failure through `set_err` with the entry index. Comments explain why.
- Keep the C core payload-opaque: it never parses Parquet or JSON.
- Keep format decisions consistent with the spec: `.zip` for every profile, ASCII archive
  names, reader-computed location columns.

## 10. Website and docs

- `index.html`, `playground.html` and `docs/*.html` are hand-written static pages with no
  build step. The docs pages link `../images/` and `../playground.html`.
- `playground.html` loads MapLibre from unpkg, the basemap from
  `data/natural-earth-countries.js` (a script so the page works from disk) and the reader
  from esm.sh at a pinned version.
- Code shown in the docs pages should run against the current bindings; update them with
  API changes.
